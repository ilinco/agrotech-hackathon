# AgroHack — мониторинг сельскохозяйственных полей

Frontend-приложение для работы с сельскохозяйственными полями, геопривязанными снимками с дрона и результатами анализа сорняков.

Приложение позволяет просматривать поля на карте OpenStreetMap, создавать и редактировать их контуры, синхронизировать снимки, запускать анализ сорняков и работать с его результатами.

## Возможности

### Реализовано

- загрузка списка полей с backend;
- создание поля по точкам, отмеченным на карте или введённым вручную;
- редактирование сохранённого контура поля;
- переименование поля;
- отображение контуров полей на OpenStreetMap;
- разметка площади поля сеткой 2 × 2 км;
- скрытие маркеров вершин на дальнем масштабе карты;
- загрузка подробной информации о выбранном поле;
- отображение количества привязанных снимков;
- синхронизация снимков из серверного каталога;
- ручная привязка существующих снимков к полю;
- обработка загрузки, пустых состояний и ошибок API;
- универсальные уведомления об успешных действиях и ошибках;
- выбор снимков и асинхронный запуск анализа;
- автоматическое обновление статуса анализа;
- история запусков и агрегированная статистика;
- показатели засорённости и рекомендации backend;
- карта и синхронизированный список обнаружений;
- выгрузка JSON, CSV, PDF и аннотированных снимков;
- синхронизируемый справочник видов сорняков;
- адаптивная навигация для настольных и мобильных экранов.

### Пока не реализовано

- загрузка файлов непосредственно из браузера — такого endpoint пока нет;
- создание ортомозаики — модель `OrthomosaicJob` описана, но API endpoints отсутствуют;
- маршруты дрона;
- полноценный offline-режим.

## Запуск проекта

### 1. Перейти в каталог frontend

Используйте путь, в который был клонирован проект.

### 2. Установить зависимости

```bash
pnpm install
```

### 3. Создать файл окружения

```bash
cp .env.example .env
```

Пример `.env`:

```dotenv
VITE_API_URL=http://localhost:8000/api
VITE_MAP_TILE_URL=https://tile.openstreetmap.org/{z}/{x}/{y}.png
```

Если `VITE_API_URL` не указан, frontend использует `http://localhost:8000/api`.

### 4. Запустить backend

Backend не входит в этот репозиторий и должен быть запущен отдельно. По текущему контракту API ожидается по адресу:

```text
http://localhost:8000/api
```

Backend также должен разрешать CORS-запросы с адреса frontend, обычно `http://localhost:5173`.

Для работы синхронизации снимков на backend должны быть настроены каталог `FIELD_PHOTOS_DIR` и остальные переменные окружения, описанные в документации backend.

### 5. Запустить frontend в режиме разработки

```bash
pnpm dev
```

Vite выведет фактический адрес приложения в терминал. Обычно это:

```text
http://localhost:5173
```

Если порт занят, Vite автоматически выберет следующий свободный порт.

### 6. Открыть приложение

Перейдите в браузере по адресу, который вывел Vite. Корневая страница автоматически перенаправит пользователя на `/map`.

## Production-сборка

Создать оптимизированную сборку:

```bash
pnpm build
```

Результат будет расположен в каталоге `dist`.

Локально проверить production-сборку:

```bash
pnpm preview
```

Проверить код линтером:

```bash
pnpm lint
```

Перед отправкой изменений рекомендуется выполнить:

```bash
pnpm lint
pnpm build
```

## Переменные окружения

| Переменная             | Назначение                            | Значение по умолчанию       |
| ---------------------- | ------------------------------------- | --------------------------- |
| `VITE_API_URL`         | Базовый URL backend API               | `http://localhost:8000/api` |
| `VITE_MAP_TILE_URL`    | Шаблон URL тайлов карты               | OpenStreetMap               |
| `VITE_MAP_ATTRIBUTION` | Обязательная подпись поставщика карты | OpenStreetMap contributors  |

После изменения `.env` необходимо перезапустить dev-сервер.

Для production рекомендуется использовать отдельный tile provider с подходящими условиями и лимитами. Публичные серверы OpenStreetMap не рассчитаны на неограниченную производственную нагрузку. Атрибуцию карты нельзя удалять или перекрывать.

## Используемые API endpoints

Страница карты и полей использует следующие ручки:

| Метод   | Endpoint             | Использование                               |
| ------- | -------------------- | ------------------------------------------- |
| `GET`   | `/fields`            | Получение списка полей и количества снимков |
| `POST`  | `/fields`            | Создание поля                               |
| `GET`   | `/fields/:id`        | Получение поля и связанных снимков          |
| `PATCH` | `/fields/:id`        | Переименование поля                         |
| `POST`  | `/fields/:id/photos` | Ручная привязка существующих снимков        |
| `GET`   | `/photos`            | Получение всех известных backend снимков    |
| `POST`  | `/photos/sync`       | Сканирование серверного каталога снимков    |

Разделы аналитики и справочника дополнительно используют:

| Метод  | Endpoint                                       | Использование                          |
| ------ | ---------------------------------------------- | -------------------------------------- |
| `GET`  | `/species`                                     | Получение справочника видов            |
| `POST` | `/species/sync`                                | Синхронизация справочника              |
| `POST` | `/analysis-runs`                               | Запуск анализа выбранных снимков       |
| `GET`  | `/analysis-runs/:id`                           | Polling статуса и получение результата |
| `GET`  | `/analysis-runs/:id/map`                       | GeoJSON обнаружений                    |
| `GET`  | `/analysis-runs/:id/export`                    | Экспорт JSON или CSV                   |
| `GET`  | `/analysis-runs/:id/report.pdf`                | PDF одного запуска                     |
| `GET`  | `/analysis-runs/:id/photos/:photoId/annotated` | Аннотированный снимок                  |
| `GET`  | `/reports/aggregate`                           | Сводка и PDF по полю и периоду         |

API-запросы и преобразование DTO находятся в `src/api`. Компоненты не формируют HTTP-запросы напрямую.

## Работа с координатами

В проекте используются два порядка координат:

- Leaflet: `[latitude, longitude]`;
- GeoJSON: `[longitude, latitude]`.

Преобразование выполняется в API-адаптерах. Не следует передавать GeoJSON-координаты напрямую в Leaflet.

Текущий backend хранит реальный полигон поля:

```json
[
  { "lat": 52.95, "lng": 63.33 },
  { "lat": 52.92, "lng": 63.39 },
  { "lat": 52.905, "lng": 63.33 }
]
```

Frontend сохраняет порядок точек и преобразует только названия координат из `{ latitude, longitude }` в `{ lat, lng }`.

Сетка внутри поля строится с шагом 2 км в локальных метрических координатах и обрезается по границе поля. Это обзорная сетка карты, а не единица агрономического подсчёта `шт/м²`.

## Работа со снимками

Текущий API не содержит endpoint для загрузки файла из браузера.

Доступный процесс:

1. Файлы помещаются в каталог `FIELD_PHOTOS_DIR` на backend.
2. Пользователь нажимает «Синхронизировать».
3. Frontend вызывает `POST /photos/sync`.
4. Backend читает EXIF и автоматически связывает снимок с полем, если GPS попадает внутрь его полигона.
5. Оставшиеся снимки можно привязать к полю вручную.

Ручная привязка через `POST /fields/:id/photos` не проверяет GPS и может переопределить автоматическое распределение.

Снимки без координат остаются видны в списке, но не отображаются на карте.

## Ошибки и уведомления

Для пользовательских уведомлений используется общий `NotificationsProvider` и хук `useNotifications`:

```tsx
const notifications = useNotifications();

notifications.success('Поле сохранено');
notifications.error('Не удалось сохранить поле', errorMessage);
notifications.warning('Снимок не содержит координат');
notifications.info('Анализ запущен');
```

Общий адаптер `getApiErrorMessage` распознаёт:

- сообщения `{ "error": ... }` от backend;
- отсутствие соединения;
- таймаут;
- `404`;
- серверные ошибки `5xx`;
- неизвестные ошибки с безопасным текстом по умолчанию.

Ошибки полей формы показываются рядом с соответствующим вводом. Критические ошибки загрузки страницы дополнительно отображаются внутри страницы с кнопкой повтора.

## Известные ограничения

- backend должен быть запущен отдельно;
- загрузка файлов из браузера пока не поддерживается API;
- frontend не выполняет нейросетевой анализ самостоятельно;
- точность координат обнаружений зависит от EXIF и GSD-допущений backend;
- offline-детекция зависит от наличия локальных весов модели на backend;
- для `OrthomosaicJob` в текущем контракте нет доступных endpoints;
- для проекта пока не настроен автоматический набор тестов.
